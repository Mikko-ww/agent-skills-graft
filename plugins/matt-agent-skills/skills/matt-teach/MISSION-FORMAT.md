# MISSION.md 格式

`MISSION.md` 位于工作区根目录。它捕捉用户学习该主题的**原因**。每一个教学决策（下一步教什么、暴露哪些资源、设计哪些练习）都应能追溯到本文档。

## Template

```md
# Mission: {Topic}

## Why
{1–3 句。用户追逐的具体真实世界目标。掌握该 skill 后，生活或工作会发生什么变化？避免「为了理解 X」这类抽象框架；追问底层结果。}

## Success looks like
- {用户将能做到的、可观察的具体事}
- {另一件具体事}
- {…}

## Constraints
- {时间、预算、既有承诺、学习偏好，以及任何约束路径的事项}

## Out of scope
- {用户明确现在不想追的相邻主题，用以保护 zone of proximal development}
```

## Rules

- **每个工作区一个 mission。** 若用户要学两件不相关的事，那是两个工作区。
- **具体优于抽象。** 「十月前跑完半马」胜过「变得更健康」。「给团队交付一个 Rust CLI」胜过「学 Rust」。
- **对含糊强硬。** 若用户说不清 why，先访谈再写任何内容。坏 mission 比没有 mission 更糟。
- **现实变化时修订。** Missions 会变。目标移动时更新本文件：不要留下过期 mission 驾驭未来会话。
- **保持短。** 若 `MISSION.md` 超过一屏，它已不再是指南针，而开始变成计划。
